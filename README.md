# Engineering Data Workbench

Version **1.0.0** · **MIT License**

一个可复用的资料管理框架：表结构驱动的查询和修订、Excel/ZIP导入、附件版本管理、操作追溯、完整备份、整库恢复，以及最近30次提交的冲突感知撤销。

仓库仅包含框架代码和空表结构，不提供业务记录、图纸、规格书、图片、模型、企业账号、租户标识或部署凭据。

## 本地运行

需要 Node.js 22.12及以上。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5273 。初始为只读用户，数据为空。界面右上角只显示身份。

启用本地管理功能时，在启动进程的环境中配置 `OWNER_TOKEN` 或 `ADMIN_TOKEN`，至少24个字符。不要把真实值写入源码或提交仓库。进入“身份切换”，输入相应凭证后启用创建人或管理员身份；凭证仅保存在当前标签页的会话存储中。

本仓库的凭证适配器用于本地开发。接入企业系统时，应替换 `server/auth.cjs`，从平台验证后的登录上下文获取真实用户ID和角色，并使用HTTPS。不会从客户端提供的角色名称或显示姓名授予权限。

## 替换为你的业务结构

编辑 `config/schema.json`：应用名称、数据表名称和字段均可修改。每个表的首列是稳定、唯一的文本记录ID，其他单元格支持文本、数字、布尔值和空值。配置文件中的 `rows` 保持空数组，业务资料通过运行后的导入入口加入。

第一次启动会生成 `.data/`，后续启动保留现有资料。修改初始schema不会覆盖已保存数据；调整已有数据结构请明确迁移范围，先备份。

## 权限与维护流程

| 能力 | 用户 | 资料管理员 | 应用创建人 |
| --- | --- | --- | --- |
| 查询当前资料 | 是 | 是 | 是 |
| 导入新记录、逐条修订、更新附件 | 否 | 是 | 是 |
| 查看操作记录 | 否 | 是 | 是 |
| 完整备份、总表替换、恢复、撤销 | 否 | 否 | 是 |

管理员的批量导入不会覆盖现有记录；已有记录通过逐条修订入口维护。每次生效保存创建一个版本，保留操作人、原因和前后值。恢复会退回目标版本之后所有人的业务修改；单次撤销保留后续对其他字段的修订，发生重叠修改则拒绝撤销。

图片支持PNG/JPG/JPEG，单张≤20MB；PDF≤100MB。附件使用内容校验值保存原文件，同名更新切换引用，历史文件继续保留。附件不会自动识别或更新表格文字。

Excel导入使用页面生成的模板，首行表头、首列文本ID，不支持公式。ZIP可以包含一份Excel和附件。备份包含当前数据、历史版本及原文件；当前数据恢复使用 `catalog.json`，`history.json`用于归档，不会冒充新系统产生的修改日志。

## 结构与扩展

- `client/`：React页面、通用数据表、身份入口和维护界面。
- `shared/`：数据模型、按记录ID计算差异、字段级撤销与冲突检测。
- `server/`：接口、认证适配器、文件存储和版本发布。
- `config/`：空业务结构。
- `tests/`：不依赖业务资料的合成测试。

快照、附件、审计、身份是独立的边界。当前文件适配器适合单进程、小型部署；多人生产使用应替换为数据库和对象存储，保持原子版本发布与并发校验，避免多个进程同时写同一文件。接飞书妙搭时，业务角色和用户ID必须来自平台验证后的上下文，附件使用平台文件SDK；不要把本地凭证适配器当作飞书登录。

```sh
npm test
npm run build
```

生产静态文件生成在 `dist/`。使用 `NODE_ENV=production` 启动服务可提供构建产物；默认仍只绑定本机回环地址，外部访问应通过受控反向代理与正式认证。
